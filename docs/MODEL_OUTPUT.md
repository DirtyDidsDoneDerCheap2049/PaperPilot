# 模型输出调整与验证

记录日期：2026-09-23。这里只验证表达规则和输出完整性，不作为研究准确率评测。

## 当前研究流程的补充说明

研究任务现在直接在对话中展示论文阅读、交叉比较、补查和报告撰写。模型返回的 `progress_summary` 随正文到达显示；内部 JSON 不展示。思考阶段只保留最多 220 字符的一行预览，不展开完整思考过程，也不把它交给报告撰写器。

Agent 会在预算内补查未执行的检索、重试失败的论文抽取，再重新分析。外部服务拒绝请求或无法获得全文时，记录实际边界，不能把“没有检索结果”当作“领域没有已有工作”。检索论文数、模型请求数和补查轮数均受限，无法保证穷尽领域文献。

最终报告另行撰写，依次按结论、候选研究空白、已有工作和本轮边界组织。结论先点名值得研究的空白；每项候选用具体缺口作标题，正文先写“空白点”，再写“与已有工作的差异”，证据不足处标“待核实”。没有有据可写的候选时直接说明，不为凑数编造。

程序检查引文编号、内部字段泄漏、必要章节及顺序。随后由模型复核，最多修订一次；有依据的待核实候选允许交付，不要求证明全球没有相关研究。提示词提醒模型不要替用户编造断言，并区分直接同范围工作与相邻工作；这不保证完全消除语义错误。失败时保留审计快照并报告失败。结构化分析另存工作区的 `.agent_history/research/`，不再插入读者报告。新格式用于之后生成的报告，历史报告不自动改写。

以下“改了什么”和八次输出对照是此前版本的记录；其中“不再调用一个模型改写答案”不适用于当前新增的研究报告撰写与复核步骤。

## API 核实与设置更正

查阅官方文档并读取实际账号的模型列表后，确认调用名为 `deepseek-flash` 和 `deepseek-v4-pro`。当前分别对应 V4.1 Flash 和 V4 Pro 0813；`deepseek-v41-flash`、`deepseek-v4.1-flash` 均不是有效调用名。下文早期测试使用的 `deepseek-v4-flash` 是兼容别名，官方已将其路由到 V4.1 Flash，不能将该测试当作旧版 Flash 的评测。[模型说明](https://api-docs.deepseek.com/quick_start/pricing/)、[更新记录](https://api-docs.deepseek.com/updates/)。

按用户选择，新工作区的常规处理和研究分析都默认使用 Flash 的 `max` 思考档位。单次输出预算设为 65,536 token，包含思考内容；单次请求超时为 600 秒。设置界面可分别调整两个角色的思考档位、输出预算和超时。应用不会因为耗时或费用自动降低思考档位。旧工作区保留已有配置，本次仅对用户指定的独立测试工作区修正无效模型名并设置 `max`。

早期记录中的 1200、4096 都是当时请求的输出预算。官方目前标示 1M 上下文、最高 384K 输出，但应用仍按阶段传入论文片段，全文抽取最多读取每篇前 60,000 字符，不能据此宣称已经支持一次完整分析任意数量全文。思考模式下 `temperature` 不生效，因此下文的“温度为 0.2”只说明测试传入了该参数，不能视为控制住了随机性。[思考模式参数](https://api-docs.deepseek.com/guides/thinking_mode/)。

本次另做三次人工片段检查：先验证 `low`、`high` 参数，再以 `max` 和 65,536 输出预算验证 JSON 返回。三次均成功；`max` 样例保留了逐字引用，并将单数据集证据判为不足以证明跨领域有效。这只能验证调用参数和这条样例的输出，不用于评价 Flash 与 Pro 的研究能力或估算实际论文任务成本。测试未发送私人论文或历史会话。

修正后的离线回归为 141 项 Python 测试通过、9 项跳过，9 项前端测试通过。新增检查覆盖思考档位、输出预算、兼容端点隔离、无效模型名和连接测试。以下保留此前的八次输出风格测试记录。

## 改了什么

普通回答、流式对话和 JSON 分析共用写作要求：先回答问题，说清依据，少用套话，保留反证和不确定性。JSON 的键、类型、状态、来源 ID 和原文引用不能为润色改动。规则在发出请求前加入，不再调用一个模型改写答案，也不对输出做文字替换。

客户端检查服务返回的结束原因。达到输出上限、内容被服务过滤或正文为空时报告失败，不把残缺回答当作完成；不会因此自动重复付费调用。流式响应在正常结束或异常退出时关闭连接。界面可能已显示部分文字，但失败的对话不会保存为完整助手回答。

对应实现：`src/llm/response_style.py`、`src/llm/deepseek_client.py`。测试：`tests/test_response_style.py`。

## 在线对照怎么做

使用现有服务配置中的 `deepseek-v4-flash`，没有测试其他模型。下面两个片段均为人工编写，不对应真实论文；未发送私人论文、历史对话或数据库记录。

```text
[P1] Abstract: We rerank retrieved passages using agreement between two retrievers. We evaluate retrieval precision on one dataset.
[P2] Methods: We train a student retriever to match a teacher's ranking distribution using KL divergence. We do not evaluate cross-domain transfer.
```

两道题分别检查普通回答和 JSON 输出：

1. 把证据一致性排序用于跨领域检索，是否已经被覆盖、能否算研究空白，接下来查什么？
2. P1 是否使用了知识蒸馏，是否证明跨领域检索有效？按 `status`、`reason`、`evidence`、`next_check` 返回，引用须保持原文。

每道题分别使用原提示和新增写作规则。温度为 0.2，每组只调用一次，没有固定随机种子，也没有统计显著性检验。

## 观察到的结果

首轮把输出上限设为 1200 token，四次调用中三次因长度限制结束；其中两次推理占满额度，正文为空。这个设置低于应用实际的 4096 上限，因此首轮不用于比较表达效果，但暴露了客户端没有识别空正文和截断的问题。

按实际 4096 上限重新执行四次调用，均正常结束：

| 检查项 | 原提示 | 加入写作规则 |
|---|---|---|
| 普通回答对研究空白的判断 | 最后断言“候选空白成立” | 开头说明现有片段不足以判断，保留待查状态 |
| 后续建议 | 提供全文、引文和检索关键词检查 | 提供具体全文检查点和可用检索式 |
| JSON 可解析、字段齐全 | 通过 | 通过 |
| 两段引用与原文逐字一致 | 通过 | 通过 |
| 把 P2 蒸馏方法误归给 P1 | 未出现 | 未出现 |

新回答仍有问题：它把相邻方法的跨域评估概括为可能的覆盖判据，没有完整核对方法和使用条件是否等价。不能仅凭这一轮输出确认研究空白，也不能据此宣称准确率提高。表达仍可能偏长，提示词无法保证每次回答都符合要求。

共进行了八次请求，服务报告合计 15,284 token，包含推理 token。没有根据公开单价推算费用，应以实际服务账单为准。这不是性能或成本基准。

## 离线与发布检查

本次 Python 回归为 133 项通过、9 项跳过，前端交互检查为 7 项通过。跳过项不计入通过数。新增测试验证输入消息不被改写、三条调用路径接入规则、JSON 修复保留约束，以及空输出、截断、连接关闭和不自动重试。

单元测试只能证明调用和错误处理行为。下一步若要评价研究效果，需要固定真实论文及全文版本，由人工标注覆盖依据、反证和不确定项，再多次对照不同模型与提示；这部分尚未完成。
