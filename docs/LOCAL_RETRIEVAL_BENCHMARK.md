# 本地全文检索资源测量

测量日期：2026-10-05。此记录评估索引和查询开销，不评估检索正确率、研究结论或模型生成速度。

在所测 32 GB 机器上，92 篇全文的首次索引约 7 分 25 秒；未变资料再次更新为 2.67 秒，30 次热查询的中位数为 169.74 ms。这些结果支持该规模下继续使用本地索引，低内存机器和更大资料库需要另测。

## 条件

- Windows；AMD Ryzen 9 8945HX，16 核、32 线程，可见内存 31.30 GiB。
- 92 篇可索引解析全文，共 6,804,140 字节、6,674,130 字符，产生 25,466 个子块。
- 多语言 MiniLM ONNX 模型，384 维，CPU 推理线程 2；模型指纹 `18ea2b07607b5936588b`，Chroma 与 SQLite FTS 混合检索。
- 在隔离副本中重新建库。SQLite 源库用 immutable 只读方式访问，并要求没有活动 WAL。
- 后端进程组包含 HTTP 应用、现有桌面 worker 和 C++ 调度器，不包含采样脚本及桌面 WebView。
- worker EXE SHA-256：`942ca0c5234d2364ef256c48843f6b232b77dbf7c537cb4aaeae891256604343`。
- 目标采样间隔为 100 ms，CPU 按 32 个逻辑处理器归一化。短于间隔的尖峰可能漏测；各进程 RSS 求和可能重复计算共享页面。

## 结果

| 阶段 | 耗时 | 平均整机 CPU | 工作集峰值 | 私有提交量峰值 |
| --- | --- | --- | --- | --- |
| 索引前空闲与接口探测 | 6.18 秒 | 0.05% | 112 MiB | 75 MiB |
| 首次索引，92 篇、25,466 块 | 445.09 秒 | 5.95% | 1,255 MiB | 2,118 MiB |
| 未变资料再次更新，全部复用 | 2.67 秒 | 2.16% | 161 MiB | 151 MiB |
| 本进程首次查询，含模型及索引加载 | 查询 1.75 秒 | 阶段平均 2.80% | 603 MiB | 1,343 MiB |
| 30 次热查询 | 中位 169.74 ms；P95 191.21 ms；最大 199.86 ms | 阶段平均 4.02% | 619 MiB | 1,358 MiB |
| 查询后空闲，观察约 6 秒 | — | 未测得新增 CPU 时间 | 618 MiB | 1,357 MiB |

整库索引采样 CPU 峰值为 17.16%，系统可用内存最低 12.82 GiB。模型在查询后留在进程中，空闲工作集比索引前约增加 506 MiB；关闭后端进程后释放。私有提交量不等于当前物理内存占用。

索引期间共 1,969 次状态、论文和任务接口探测，没有失败，合并 P95 为 48.52 ms、最大 97.71 ms。热查询由六个中英文问题各重复五次组成，没有查询结果缓存，每次返回八项；命中正确率未评分。

| 磁盘内容 | 字节 |
| --- | --- |
| 模型文件 | 135,405,027 |
| 运行中的索引，含临时日志 | 142,679,936 |
| 后端关闭后的稳定索引 | 133,533,696 |

模型与稳定索引合计约 256.48 MiB，不含论文和软件依赖。索引与检索没有外部模型请求，也没有 embedding API 费用；后续研究分析仍可能付费。

## 已知等待

首次查询的 1.75 秒中，同时发起的状态接口也等待约 1.75 秒。[PaperRetriever.search](../src/knowledge/paper_retrieval.py) 持有检索锁，[状态路由](../src/server/routes_library.py)同步读取同一锁，冷加载期间会阻塞响应。热查询并发探测的状态请求最大为 175.5 ms。

该问题尚未因这次测量修复。改进应使用不争用检索锁的状态快照或后台读取，再复测接口等待，不必因此改成远程向量服务。

## 复测

在准备好源码依赖、模型、原生内核和桌面 worker 后，关闭源工作区应用：

```powershell
.venv/Scripts/python.exe -m pip install -r requirements-dev.txt
.venv/Scripts/python.exe scripts/benchmark_local_retrieval.py --source D:/ReaderData/research
```

脚本仅测 SQLite，拒绝活动 WAL 和已存在的测试副本。输出固定在 `work/testing/current/local-retrieval-benchmark`；重测前保留所需测量证据，再仅清理该副本。普通 pytest 也使用 `work/testing/current`，两者不能同时运行。

首次加载指进程首次加载，系统文件缓存可能已预热，不是整机重启后的磁盘冷启动。记录不覆盖下载、PDF 解析、屏幕帧率、功耗、电池续航或整轮研究时间，也不能推广为上万篇论文的性能承诺。
