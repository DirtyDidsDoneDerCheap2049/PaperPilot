# 桌面版架构与边界

产品目标是围绕具体创新方向查已有实现、核对反证、收窄可验证的研究空白，见 [原始需求与实现边界](PRODUCT_PURPOSE.md)。处理几十篇论文是建立方向认识所需的能力。

## 当前取舍

采用 B：C++ 本地任务内核 + Python 分析进程。C++ 负责领取、状态转换、幂等键、执行代次和互斥；Python 保留论文工具链。使用本地 JSON Lines 管道，没有额外 HTTP 微服务。

全部重写成 C++ 会把时间花在模型 SDK 和解析适配上，当前收益不足。混合语言仍增加编译、进程通信、排错和打包成本，测试与构建脚本用于约束这些成本。

2026-09-22 按桌面体验重新选择：默认内置 SQLite，MySQL 可选。单机串行研究任务不需要用户维护数据库服务；把 MySQL 设为必选增加了首次使用与故障处理成本。MySQL 的事务、约束和排错实现仍保留，但不作为普通用户的入门条件。既有 MySQL 工作区继续按保存配置连接，故障时不自动回退；切换后端不会自动迁移资料。

## 请求到结果

```text
pywebview 窗口 → 回环 FastAPI / WebSocket
  → TaskService → JSON Lines → C++ reader_tasks → SQLite / MySQL jobs / events
  → 独立 Python worker → 检索 / PDF / 模型 / 证据 / Orchestrator
  → SQLite / MySQL 研究表 + 本地报告文件 → 任务终态 → UI
```

入口：`src/app/desktop.py`。装配：`src/app/factory.py`。任务：`src/runtime/tasks.py`、`native/main.cpp`。主报告仍由 Orchestrator 生成。SessionRAG、RecoveryManager 独立模块保留，未宣称它们是主流程恢复机制。

桌面只监听 127.0.0.1 随机端口，校验 Host、Origin 与修改请求头。没有多用户登录、远程租户隔离或公网部署能力；本机恶意进程不在该保护边界内。

## 任务协议

每行 JSON 请求对应一个响应。submit 在事务中持久接收；相同幂等键和内容返回旧任务，不同内容冲突。同会话不可同时提交两个活跃任务。claim 原子领取并增加 token；finish / event 必须匹配当前 token。

queued → running → succeeded / failed。取消经过 cancel_requested → cancelled。启动发现旧 running / cancel_requested 时标记 interrupted，不自动重复付费。queued 保持排队并可在下次启动执行。retry 显式重新排队，从流程起点运行，可能复用画像，不是任意步骤断点续跑。

Windows 文件句柄 / POSIX flock 保护工作区，MySQL GET_LOCK 防止多个内核同时使用同一数据库。C++ 以 RAII 管理连接、预处理语句和锁。父管道 EOF 时 worker 退出。正常关闭先停止 worker，再释放数据库。一个数据库对应一个工作区，目前没有多租户隔离。

这不是端到端 exactly-once：外部 API 可能已收费，本地尚未确认响应。token 保护任务库终态，不能撤销供应商请求。

## 证据与成本

模型返回必须是 JSON 对象；创新画像验证字段、置信度和证据类型。引文匹配解析文本，记录路径、SHA-256、字符范围。不能绑定的引文不作为直接全文证据；supports 不得补出原句没有的教师、损失或方向。

融合、预训练、冻结和 attention 不自动等于蒸馏。否定表达不作正向蒸馏证据。Critic 修改的结论保留为待复核草案。这些是保守约束，不是内容正确性的保证。

所有研究方向共用 `src/analysis/direction_coverage.py`，根据当前主张与已验证原文建立覆盖索引，不再按领域切换专用矩阵。`method_component` 使用论文的组件名称；迁移任务的 `source_task` / `target_task` 和其他方法事实分别附原文证据 ID。蒸馏的四项证据校验适用于任意任务，原文定位与关键词检查仍不能证明语义蕴含。候选还需最近工作差异、来源 ID、判别实验与逐项 Critic。见 [通用研究流程](DOMAIN_PROFILES.md)。

旧的 `stereo_matching_stage` 仅作为 `method_component` 的读取别名，不写入新结果、不触发分支。历史 `off_topic` 和画像 `is_relevant=false` 不再全局排除新研究中的论文；本轮审计重新核查相关性，提取错误仍列为失败。删除了固定书目导入器、领域先验模块及专用实验生成代码，历史资料保留。

初始检索按工作区配置执行，最多 12 条查询，缺省 6 条（旧工作区保留原配置）。Semantic Scholar 和 arXiv 无结果时尝试 Crossref，各来源失败与正常零结果分别记录。候选形成后最多自动补查两轮，每轮缺省 6 条查询、补读 8 篇新论文；没有新文献则停止重复检索。新资料进入解析、证据抽取及重新综合，训练实验不在当前工具范围。可选 MCP 来源仍有内部吞掉异常的路径。

方向解析保存本轮研究问题和原始请求。连续追问会读取上一轮结构化方向、最近消息，以及最近研究中正式/待验证/否决候选各前 8 项的内容和待办；历史状态作为待复核上下文，不作为新证据。

研究 worker 使用流式 Chat Completions，正文片段写入持久任务事件；思考仅记录最多 220 字符的单行预览，不拼入报告。对话内组件通过游标 SSE 回放与订阅，以 attempt_token 隔离重试，支持排队转运行时令牌变化。界面只显示模型生成的阅读摘要和报告草稿，不枚举内部 JSON 字段；刷新按 160ms 合并。完整输出仍需通过字段、证据和报告检查。旧版未记录的片段无法补回。兼容服务须支持 stream 参数，尚未逐家验证厂商。

抽取统计区分成功与失败；正文哈希匹配且引用已绑定的画像可复用，失败结果不覆盖旧画像。先验笔记不计入论文全文证据。Critic 检查正式和待验证候选，后者不会因措辞润色自动升格。报告作者只接收证据、候选与实际检索结果，另一次模型检查核对直接回答、引用和夸大结论，失败后允许修订一次；仍失败则任务失败。审计对象保存在 .agent_history/research，正文不包含内部 JSON。模型复核不能代替人工科研判断；历史报告不改写。

研究资料包按指定会话、报告或选中论文确定范围，不回退到其他会话的最新报告。导出 Markdown、JSON、校验清单和 ZIP，保留截断与省略说明；画像来自当前资料库，并非历史报告生成时的快照。已知密钥和本地绝对路径会脱敏，但论文和研究内容仍需用户自行检查后分享。

兼容服务使用 OpenAI Chat Completions 协议。可配置 max_tokens / max_completion_tokens / 不发送长度参数、JSON 模式及有限的附加参数；模型列表不受支持时允许手填模型。自动模式只向官方 DeepSeek 发送其专用参数，也允许显式选择能力模式。这不涵盖 Responses 或 Anthropic 原生协议。

研究预算由设置配置，默认最多 200 次模型请求、120 分钟。新 DeepSeek 工作区的常规处理和研究分析均使用 `deepseek-flash`、`max` 思考档位；单次输出预算为 65,536 token（含思考），请求超时为 600 秒，均可在连接设置中调整。思考参数只发送给官方 DeepSeek 端点，其他兼容端点不附带这些参数。SDK 重试关闭，应用有限重试计入调用总数。提交时把调用次数和任务时限写入任务 payload，协调器与 worker 使用同一预算快照。上述预算是应用设置；全文抽取仍只读取每篇前 60,000 字符，尚未充分利用模型长上下文。输入 token、嵌入、云解析没有统一金额预算或账单核算，用户需设置供应商额度。

新工作区默认尝试处理 50 篇全文，设置允许 0–100 篇。ParseAgent 逐篇反馈进度，EvidenceGroundedAnalyzer 每批最多审计 8 篇画像；Orchestrator 保存完整逐篇清单，未提取或未审计资料不会静默消失。继续同一研究会话会承接上一轮论文集合。这里的 Agent 是固定研究阶段编排，目前没有动态计划、多轮自主搜索或并行 Subagent 调度。

## 存储与剩余问题

- MySQL 使用 InnoDB、utf8mb4、UTC 会话和预处理参数；保留研究表结构，增加顺序列及任务表。历史报告不重写，测试使用隔离数据库。
- 报告文件、研究库和任务库没有共同事务。恰在报告落盘后中断，可能留下报告或消息，但任务显示 interrupted；先核对结果再重试。仍需 job_id 暂存产物、发布清单和恢复对账，不能宣称跨存储原子提交。
- 解析文本会更新，哈希能发现来源变化；尚未保存每次解析的不可变全文版本，历史复现依赖备份。
- 报告重命名、删除仍是文件与数据库两步修改，尚无统一回滚日志。重要结果先备份。
- 本地文本检索与向量相似度不是同一算法。向量服务按配置分开索引，尚无自动重建旧索引。
- 有数据库初始化兼容逻辑，尚无完整版本化迁移与回滚。第一次接入旧工作区应在副本验证。
- 上传检查 PDF 头及 50 MB 上限，不是恶意 PDF 沙箱。任务进程隔离也不是操作系统权限沙箱。

## 可验证的工程经历

通用后端：异步 API、幂等冲突、状态机、事务、故障恢复、配置保护、打包和发布检查。C++：RAII、MySQL C API 与预处理语句、跨平台文件锁、进程协议、构建与调试。AI 应用：证据来源、结构校验、保守降级与离线回归。

C++ 内核当前单线程串行处理，不支撑“熟练高并发网络编程”或网络 I/O 调优的表述。接入数据库不等于掌握索引优化、分布式事务和大型服务运维。应依据代码、调试记录、测试和演练说明掌握程度。

下一轮优先补跨存储结果发布与恢复对账、固定论文集人工评估。没有使用反馈前不扩大服务拆分。
