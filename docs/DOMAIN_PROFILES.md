# 通用论文研究方向解析

更新：2026-09-23。PaperPilot 围绕用户提出的研究方向检索、批量解析论文、比较方法、核对证据并分析已有覆盖与待验证问题。产品不按学科设置使用门槛；受作者研究背景和当前验证范围所限，现阶段更适合深度学习方向的研究者使用。

## 统一流程

1. 解析问题、目标任务、方法机制与待核查主张。
2. 按预算检索已有实现、同义方法和反证，合并用户提供的论文。
3. 获取与解析全文，逐篇抽取方法、实验、局限和原文引句。
4. 分批核查主张，建立论文—主张—证据索引，记录已有覆盖、部分覆盖和证据不足。
5. 综合最近工作差异与候选空白，由 Critic 逐项核查，提出判别实验。
6. 保存论文、报告与讨论；用户补资料或提出新想法后继续同一会话。

## 字段与证据

| 字段 | 用途 |
|---|---|
| `research_question` / `claims_to_verify` | 问题与主张；用户的新颖性判断不是事实 |
| `research_domain` / `target_task` | 领域与目标问题，不限预设名单 |
| `method_component` | 方法组件或处理环节，使用当前论文术语 |
| `method_category` / `method_subcategory` | 方法类别与具体机制 |
| `implementation_details` / `search_queries` | 实现差异及检索式 |
| `method_facts` | 任务、机制、来源任务、目标任务等事实；每项附原文证据 ID |

`matrix_axes_hint` 是给模型的比较维度建议，不能据此宣称已实现任意维度的自动研究地图。确定性索引以主张和方法关系为轴，不把空单元格解释为研究空白。

涉及知识蒸馏时，另核对教师信号、学生、模仿目标、匹配损失四项原文依据；不涉及则无需这些字段。这是通用机制校验，不限定应用任务。融合、冻结编码器、初始化或 attention 算子本身不证明蒸馏。原文定位成功也不保证模型正确理解原文，仍需要语义核查。

## 已移除的个人特化

- 固定论文名单、立体关键词过滤和检索排序加权。
- 立体阶段枚举、教师类别矩阵、视差/极线目标分类和实验模板。
- 内置立体先验模块及固定领域书目导入器。
- 笔记目录、导出指令和报告中的立体任务默认值。
- 蒸馏关键词优先挤占其他方法证据的抽取后排序。

历史 `stereo_matching_stage` 只读入为 `method_component`，新结果不再输出它。历史论文、先验笔记、对话和报告不删除、不改写；先验笔记不作为原论文证据。旧 `off_topic` 和画像相关性标记不再全局排除其他方向的研究，由本轮审计重新判断。

`scripts/rewrite_latest_report.py --workspace <副本路径> --remap-only` 离线重新定位原文引用并输出新报告。离线模式不做语义裁决，旧候选降为待复核；`--reanalyze` 才使用配置的模型重新审计已有论文，可能产生费用。两种模式都不扩展检索，也不改写旧报告和已保存的分析。

## 验证边界

`tests/test_generic_agent.py` 检查不同领域问题经过统一的解析、画像、审计与报告链路，并覆盖引用伪造、缺失机制依据、摘要/先验排除、模型失败、旧数据兼容和跨方向复用。立体匹配也仅作为普通输入经过同一条流程。50 篇合成 PDF 回归检查逐篇状态、解析上限和分批审计。

这些验证程序行为，不代表所有领域的研究结论准确率。当前仍是固定阶段编排：尚无反证驱动的自主多轮检索、关键主张按需回读长文、完整的结论变化追踪。真实论文的覆盖遗漏、引用解释和候选质量需要分方向人工评估。
